Flash sales give products discounted prices for a limited window. Vendors submit products for participation, which a superAdmin must approve before the product is discounted.

## Flash sale shape

| Field | Type | Notes |
|-------|------|-------|
| `id` | string | UUID |
| `name` | string | Sale name |
| `description` | string? | Optional description |
| `discountPercent` | int | Must be between `1` and `90` |
| `startsAt` | string | ISO 8601, when the window opens |
| `expiresAt` | string | ISO 8601, when the window closes |
| `isActive` | bool | Default `true` |
| `products` | json? | Optional product payload |
| `deletedAt` | string? | Set on soft delete |

## Participant status workflow

Each participation has a `status`:

`pending` → `approved` | `rejected`

A vendor's `join` creates a `pending` participant. A superAdmin then approves or rejects it; only `approved` participants see the discounted price.

## Endpoints

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/flash-sales/active` | Public | Currently active flash sales |
| POST | `/flash-sales/join/:flashSaleId` | vendor | Submit a product for a flash sale |

## GET /flash-sales/active

Public. Returns the sales that are active, not deleted and currently within their window (`startsAt ≤ now ≤ expiresAt`), ordered by soonest expiry. Each sale includes a `participantsCount`.

<CodeBlock title="Response">
```json
[
  {
    "id": "...",
    "name": "Back to School",
    "description": "School supplies at a discount",
    "discountPercent": 25,
    "startsAt": "2026-08-07T00:00:00.000Z",
    "expiresAt": "2026-08-09T23:59:59.000Z",
    "isActive": true,
    "products": null,
    "participantsCount": 4
  }
]
```
</CodeBlock>

## POST /flash-sales/join/:flashSaleId

Vendor submits one of their own products. Body:

```json
{ "productId": "..." }
```

`productId` is required. Returns `201` with the new participant in `pending` status.

| Status | Condition |
|--------|-----------|
| `400` | No `productId`, sale not currently active, product already submitted, or tier participation cap reached |
| `403` | Product does not belong to the vendor's business |
| `404` | Flash sale or product not found |
| `503` | `flash_sales` feature flag disabled |

Participation is capped by the vendor's subscription tier, counting `pending` + `approved` participants:

| Tier | Max active participations |
|------|---------------------------|
| `free` | 1 |
| `pro` | 3 |
| `business` | 5 |
| `enterprise` | 10 |

<Callout type="note">
Joining a flash sale only creates a `pending` participation — a **superAdmin must approve** it before the product is included in the sale.
</Callout>

<Callout type="note">
Admin flash-sale management is documented in the restricted [Admin API reference](/en/developers/api-admin).
</Callout>
