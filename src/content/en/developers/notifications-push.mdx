Notifications keep users in the loop. The backend delivers them through three channels: **in-app**, **Expo push** (mobile), and **web push** (browser).

## Channels

| Channel | Mechanism | When |
|---------|-----------|------|
| In-app | `Notification` rows + socket.io emit | Always |
| Expo push | `expoPushToken` on the user, `expo-server-sdk` | Mobile apps |
| Web push | `WebPushSubscription` + web-push library (VAPID) | Browser |

## Registering for push

Both mobile and web use the same endpoint, `POST /api/notifications/register-token`:

```bash
# Mobile (Expo token)
curl -X POST https://api.sokopluss.co.tz/api/notifications/register-token \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"token": "ExponentPushToken[...]"}'

# Web (push subscription)
curl -X POST https://api.sokopluss.co.tz/api/notifications/register-token \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"type": "web", "endpoint": "...", "p256dh": "...", "auth": "..."}'
```

For web push, pass `type: "web"` with the subscription's `endpoint`, `p256dh` and `auth`. Without `type`, the body's `token` is stored as the user's Expo push token.

## Preferences

Users can mute notification types via `GET/PUT /api/notifications/preferences`.

| Preference | Controls |
|------------|----------|
| `order_updates` | Order status, delivery, escrow |
| `promotions` | Promos, boosts, coupons |
| `general` | Everything else |
| `channel` | `sms` (default) or `email` for non-push delivery |

## What triggers a notification

- Order placed / status changed
- Delivery assigned / verified
- New message
- Vendor approval / rejection
- Payment or refund events
- Feature flag toggles (broadcast by audience)

## Sending notifications (admin)

Admins with the `send_messages` permission send targeted or role-based notifications through a single endpoint:

| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/notifications` | Send to `userId`, `userIds` or `roles` |

```json
{
  "roles": ["vendor"],
  "type": "admin",
  "title": "Platform update",
  "message": "New commission rates take effect on Monday."
}
```

The response reports `count`, `smsSent`, `emailSent`, `pushSent` and `webPushSent`. Role targeting is bounded by the caller's role: `superAdmin` can target every role, while `majorAdmin` and `partnerAdmin` can target a subset.

<Callout type="note">
Role broadcasts fan out to every matching user and registered token. Use `userId` or `userIds` for targeted notices.
</Callout>

## Security notes

- Never log `expoPushToken` or VAPID private keys.
- VAPID keys belong in env vars (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`).
- Respect user preferences before sending promotional pushes.
